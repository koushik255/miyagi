  User "1" --> "many" Group : manages as professor
  User "1" --> "0..many" GroupMember : assigned as student
  Group "1" --> "many" GroupMember : has students
  Group "1" --> "1..many" Project : assigned projects
  User "1" --> "many" Project : assigns as professor
  User "1" --> "0..many" Project : assigned as student
  Project "1" --> "1" Repository : has one repo
  Project "1" --> "many" FileNode : indexed files
  Repository "1" --> "many" CommitActivity : tracks commits

  BackendAPI --> Database : reads/writes
Assumptions: users can be professors or students; professors create and manage groups; students are assigned to groups; professors can assign projects to individual students within a group; each project has one repository; Git activity and file trees are synced through normal backend API calls. Real-time presence/collaboration is intentionally left out of the v1 design.
